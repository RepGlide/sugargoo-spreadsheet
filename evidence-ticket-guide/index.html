Evidence Ticket Guide

Turn one sheet clue into a source, visible content, unknown item, and stop condition.

One clue, one ticket

Every clue in a sheet is an observation waiting to be organized. An Evidence Ticket gives each clue five fields so the observation stays an observation — and never quietly turns into a claim about the product, the seller, or the link.

Field 1 — Source cue

Record where the clue came from: the sheet, a category page, or the current target page. A clue means different things in different places, so the source must come first.

Field 2 — Visible option

Write down what the page clearly shows — the color, size, version, quantity, or other option. Only what is explicitly displayed belongs here.

Field 3 — Current context

Note the title, image, numbers, and labels on the actual page the clue points to. Context is what lets you read the option correctly.

Field 4 — Open question

Mark what is still missing, conflicting, or unconfirmable. An open question stays open until the page resolves it; it is never answered from habit.

Field 5 — Stop condition

Write what should make you stop — a missing source, an assumed option, a skipped context — instead of filling in a guess to complete the ticket.

Ticket ruleA ticket organizes observations. It does not verify a product, seller, or link, and it never fills a blank with a guess.
✂Tear off: any line that now reads as verification instead of observation.

A worked ticket

  1. Source cue: noted as the sheet row or the target page.
  2. Visible option: only the color, size, or quantity the page shows.
  3. Current context: the title, image, and labels, recorded.
  4. Open question: what is missing, marked not guessed.
  5. Stop condition: when to halt and re-check.

Research ticket example — not a product record, recommendation, verification, or saved activity.
